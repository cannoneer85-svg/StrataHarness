# Версия Шаблона — SemVer в `VERSION` и git-теге

Раньше `template-version` в Реестре был «дата + sha»: по нему нельзя понять, ломает ли обновление Проект, и нельзя показать, что изменилось. Перед open-source публикацией переходим на SemVer: источник истины — файл `VERSION` и аннотированный тег `vX.Y.Z`, первый Релиз — `v1.0.0`. В Проекте пишется `template-version: vX.Y.Z (<sha>)`: версия — для людей и сравнения, sha — чтобы `-Mode Update` по-прежнему доставал базовые файлы из git. MAJOR для Шаблона означает «ломает `-Mode Update` у существующих Проектов» (удаление/переименование скилла, параметры `Initialize-Project`, формат Реестра, маршруты и guardrails `AGENTS.md`), а не изменение API библиотеки.

## Considered Options

- **Оставить «дата + sha», SemVer только для GitHub Releases.** Отклонено: две несвязанные системы версий, Update не может сказать «вы пропустили MAJOR».
- **CalVer (`2026.10`).** Отклонено: не сообщает о ломающих изменениях, а для Шаблона это главное.

## Consequences

- Старый формат остаётся читаемым: Update трактует его как версию ниже `1.0.0` и мигрирует поле.
- `Test-Template.ps1` сверяет `VERSION` с верхней секцией `CHANGELOG.md`.

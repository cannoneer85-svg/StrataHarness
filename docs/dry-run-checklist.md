# Чек-лист пробного прогона (Seam D)

Чек-лист для ручной валидации Шаблона end-to-end перед релизом или после крупных изменений архитектуры и скиллов.
Спека: `docs/specs/0001-template-v2-spec.md` (Seam D, история 46, критерий 16).

> **Примечание:** Этот документ относится к Метадокументам Шаблона (`Meta` в манифесте) и удаляется при инициализации нового Проекта. Прогон выполняется человеком (или под контролем человека) после завершения разработки и прохождения тестов.

- [ ] Установлен PowerShell 7 (`pwsh`).
- [ ] Установлен `git` (версия ≥ 2.30).
- [ ] Доступен Antigravity (с поддержкой `ask_question`).
- [ ] Доступны целевые AI-инструменты (Claude Code, Cursor, Codex).
- [ ] Все юнит-тесты шаблона в `/tests/` зелены (`Invoke-Pester ./tests`).
- [ ] Валидатор шаблона успешен (`pwsh -NoProfile -File .agents/scripts/Test-Template.ps1` возвращает код `0`).

## 2. Инициализация тестового Проекта (режим New)

Цель: проверить корректность работы [Initialize-Project.ps1](../.agents/skills/init-project/scripts/Initialize-Project.ps1) при создании чистого репозитория.

### Шаги

1. Создать чистую временную папку вне текущего репозитория (например, `$env:TEMP/dry-run-project`).
2. Скопировать всё содержимое репозитория Шаблона во временную папку (или сделать `git clone` / использовать GitHub «Use this template»).
3. В корне временного проекта запустить инициализацию:
   ```powershell
   pwsh -NoProfile -File .agents/skills/init-project/scripts/Initialize-Project.ps1 -Mode New -Tracker local
   ```

### Ожидаемый результат

- [ ] **Метадокументы Шаблона удалены:**

  - В `docs/specs/`, `docs/adr/`, `docs/handoff/`, `docs/analysis/`, `docs/research/` удалены метадокументы Шаблона.

  - В заголовке `.agents/SKILLS.md` появились строки `- **template-version:** <hash>` и `- **template-source:** <url/path>`.
- [ ] **Трекер задач настроен:**
  - В `docs/agents/issue-tracker.md` записана конфигурация для выбранного трекера (`local`).

## 3. Сквозной прогон задачи Minor в Antigravity

Цель: проверить соблюдение маршрута Minor, стоп-гейтов и корректность связки этапов.

### Сценарий: добавить простую функцию/утилиту

1. **Шаг 0 — Классификация:**
   - Открыть тестовый проект в Antigravity.
   - Сформулировать задачу (например: «Добавь строковую утилиту `slugify`»).
   - **Проверка:** Агент в первом сообщении объявляет:
     - `Type: Development`
     - `Category: Minor` с кратким обоснованием по признакам из [AGENTS.md](../AGENTS.md).
   - Агент останавливается и ждет подтверждения пользователя (стоп-гейт).

2. **Этап 1 — Интервью:**
   - Пользователь подтверждает маршрут Minor.
   - **Проверка:** Агент запускает [grill-with-docs](../.agents/skills/grill-with-docs/SKILL.md) и задаёт вопросы через интерактивный инструмент `ask_question`.
   - Квота Minor соблюдена: ровно 1 раунд, 2–4 вопроса (контур, спецсимволы, регистр).
   - По завершении раунда агент выдаёт резюме и запрашивает переход к реализации (стоп-гейт).

3. **Этап 4 — Реализация (In-Place, TDD):**
   - Пользователь подтверждает переход к реализации.
   - **Проверка:** Агент выбирает стратегию `In-Place` (так как задача Minor, 1 модуль, укладывается в Smart zone ≈120k).
   - Агент фиксирует `BASE_COMMIT` (или начальную точку) и пишет тест первым (Red → Green → Refactor).
   - Все тесты становятся зелёными.
   - Агент останавливается и запрашивает разрешение на `/code-review` (стоп-гейт).

4. **Этап 5 — Ревью:**
   - Пользователь разрешает `/code-review`.
   - **Проверка:** Агент выполняет ревью по двум осям:
     - **Standards:** соответствие стандартам из `CODING_STANDARDS.md`.
     - **Spec:** соответствие требованиям из интервью.
   - Замечания ревью устраняются (при наличии).
   - Агент останавливается и ожидает явную команду на закрытие.

5. **Этап 6 — Закрытие (`/close-task`):**
   - **Проверка guardrail:** агент ни при каких условиях не коммитит и не закрывает задачу сам.
   - Пользователь даёт явную команду: «закрывай задачу» или «фиксируй».
   - **Проверка:**
     - Формируется handoff-документ в `docs/handoff/`.
     - Обновляется `docs/handoff/LATEST.md`.
     - Очищается `.scratch/`.
     - Создаётся git-коммит с заданным форматом сообщения.
     - `git push` **НЕ** вызывается.

## 4. Проверка подхвата правил и скиллов в окружениях

Цель: убедиться, что правила, скиллы и ограничения видимости работают во всех поддерживаемых средах.

### Claude Code

- [ ] Правила подхватываются через [CLAUDE.md](../CLAUDE.md) (ссылка `@AGENTS.md`).
- [ ] Скиллы видны как слэш-команды из `.claude/skills/`.
- [ ] Ручные скиллы этапов (`to-spec`, `to-tickets`, `implement`, `handoff`, `close-task`, `init-project`, `analyze`) имеют `disable-model-invocation: true` и не вызываются моделью произвольно.
- [ ] Обычные скиллы (например, `tdd`, `codebase-design`) доступны модели для автономного вызова.

### OpenAI Codex / Codex CLI

- [ ] Правила подхватываются из корневого [AGENTS.md](../AGENTS.md).
- [ ] Размер [AGENTS.md](../AGENTS.md) строго меньше 32 KiB (и менее 24 KB для совместимости).
- [ ] Скиллы подхватываются из `.agents/skills/`.
- [ ] Настройки `agents/openai.yaml` корректно ограничивают вызов (`allow_implicit_invocation: false` для ручных скиллов).

### Cursor

- [ ] Правила подхватываются из корневого [AGENTS.md](../AGENTS.md).
- [ ] Скиллы обнаруживаются агентом.
- [ ] Проверка дублирования: проверить, не возникают ли конфликты или дублирование описаний скиллов из-за одновременного наличия `.agents/skills/` и `.claude/skills/`.

## 5. Ручные проверки валидатора (`Test-Template.ps1`)

Цель: подтвердить, что скрипт валидации отлавливает все типичные нарушения структуры.
Подробный протокол проверки описан в `.scratch/template-v2/validator-manual-checks.md`.

Скрипт автоматизированного прогона:
```powershell
pwsh -NoProfile -File .scratch/template-v2/validator-manual-checks.ps1
```

Проверяемые случаи:
- [ ] **Случай 0:** Базовый прогон на чистой копии (код `0`).
- [ ] **Случай 0b:** Запуск из вложенной папки (код `0`).
- [ ] **Случай 1a:** Папка скилла создана, но не внесена в [SKILLS.md](../.agents/SKILLS.md) (код `1`).
- [ ] **Случай 1b:** Скилл удалён из [SKILLS.md](../.agents/SKILLS.md), папка осталась (код `1`).
- [ ] **Случай 1c:** В [SKILLS.md](../.agents/SKILLS.md) внесён несуществующий скилл (код `1`).
- [ ] **Случай 1d:** Дублирование записи в [SKILLS.md](../.agents/SKILLS.md) (код `1`).
- [ ] **Случай 2:** Поле `name` в `SKILL.md` не совпадает с именем папки (код `1`).
- [ ] **Случай 3a–3c:** Рассинхронизация флагов ручного запуска между `SKILL.md` и `agents/openai.yaml` (код `1`).
- [ ] **Случай 4a–4e:** Битые ссылки в документации и скиллах (код `1`), ссылки внутри блоков кода игнорируются (код `0`).
- [ ] **Случай 5a–5b:** Проверка отсутствия устаревшего `.agents/AGENTS.md` (при наличии — код `1`, при отсутствии — код `0`).
- [ ] **Случай 6a–6b:** Проверка размера `AGENTS.md` (≥ 24000 байт — код `1`, < 24000 байт — код `0`).

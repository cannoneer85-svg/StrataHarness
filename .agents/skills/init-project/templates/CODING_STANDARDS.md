# Стандарты кодирования

Правила оформления, архитектурные ограничения и соглашения по коду для этого проекта.
Используются при автоматическом код-ревью (`/code-review` по оси Standards).

## Общие принципы

- Простота и читаемость кода превыше преждевременных оптимизаций.
- Глубокие модули: простой интерфейс скрывает сложную реализацию.
- TDD: сначала тесты, проверяющие наблюдаемое внешнее поведение (red-green-refactor).
- Обработка ошибок явная, без замалчивания исключений.

## Тестирование и производительность проверок

Проект разделяет тесты на два уровня по скорости и скоупу:
- **Быстрые юнит-тесты (`test:unit` / `test:fast`)**: время выполнения < 5–10 секунд. Тестируют изолированную бизнес-логику без поднятия баз данных, Docker-контейнеров, сетевых вызовов или браузера. Запускаются разработчиками и агентами в цикле TDD (`red → green → refactor`), в тикетах и после правок по ревью.
- **Тяжелые интеграционные и E2E тесты (`test:integration` / `test:all`)**: проверяют сквозные сценарии, миграции БД, контейнеры или UI. Запускаются **ровно один раз** перед коммитом на этапе `/close-task` (Preflight) и в CI на pull request. Субагентам в тикетах запрещено запускать их без явной необходимости.
